# Лабораторная работа №3 — растровые алгоритмы

Приложение на C# Windows Forms для трёх частей задания.

## Запуск

В PowerShell из папки проекта:

```powershell
dotnet run
```

Требуется Windows и .NET 8 SDK или новее.

Проверка расчётов — отдельный проект без интерфейса:

```powershell
dotnet run --project Checks
```

## Использование

1. В режиме **«Рисовать границу»** выберите цвет кнопкой **«Граница»**, затем удерживайте левую кнопку мыши и нарисуйте замкнутый контур. По умолчанию цвет границы чёрный. Внутри можно нарисовать дополнительные замкнутые контуры — отверстия.
2. Выберите **«Заливка цветом»**, при необходимости измените цвет и щёлкните внутри контура. Применяется рекурсивная заливка горизонтальными сериями пикселов с четырёхсвязностью.
3. Для **«Заливки рисунком»** сначала загрузите графический файл, затем щёлкните внутри области. Рисунок не масштабируется: маленький повторяется по обеим координатам, большой используется в натуральном размере.
4. Для **«Обхода границы»** можно открыть произвольное изображение либо использовать нарисованное. Щёлкните по пикселю цвета нужной границы. Восьмисвязный компонент этого цвета обходится методом Мура; красная линия накладывается поверх исходного изображения, зелёная точка обозначает начало. Кнопка **«Сохранить границу»** записывает точки в порядке обхода как `номер X Y`.
5. Для **«Отрезка Брезенхемом»** и **«Отрезка Ву»** щёлкните начало и конец отрезка либо протяните его мышью. Цвет берётся из кнопки **«Граница»**. Пока отрезок не зафиксирован, на холсте видны только пунктирный предпросмотр и оранжевая точка начала; сам алгоритм выполняется один раз, вторым щелчком или отпусканием кнопки. В строке состояния выводятся координаты концов, длина отрезка и число закрашенных пикселей.

Размер холста можно изменить в полях **«Холст»**: введите ширину и высоту в пикселах и нажмите **«Изменить размер»**. Существующий рисунок остаётся в левом верхнем углу без масштабирования. При увеличении добавляется белое пространство, при уменьшении обрезаются правый и нижний края. **«Новый холст»** очищает изображение, сохраняя установленный размер.

Алгоритмы сравнивают цвета пикселов точно. Для надёжного обхода загружаемая граница должна иметь один цвет; изображения JPEG могут содержать близкие, но разные оттенки из-за сжатия.

Заливка работает только внутри замкнутого контура. Если выбранная область доходит до края холста, программа не меняет изображение и предлагает замкнуть контур.

## Рисование отрезка

Реализация вынесена в `Task2.cs` в виде статического класса `Task2` с перечислением `LineAlgorithm`:

- `Task2.BresenhamPoints(from, to)` — целочисленный алгоритм Брезенхема, возвращает список пикселей отрезка. Накапливается ошибка смещения, по её знаку выбирается шаг по старшей оси; деление и вещественные числа не используются. Число точек равно `max(|dx|, |dy|) + 1`, соседние точки восьмисвязны, отклонение от идеальной прямой не превышает половины пикселя, а результат не зависит от порядка концов и от того, какая координата передана первой.
- `Task2.DrawWu(image, from, to, color)` — алгоритм Ву со сглаживанием. Шаг делается по старшей оси, а в каждой позиции закрашиваются два соседних пикселя с взаимно дополнительной прозрачностью, пропорциональной дробной части ординаты: `cover = rest * 255 / dx`, пиксель текущей строки получает `255 - cover`, соседний — `cover`. Дробная часть хранится как целочисленный числитель `rest` в диапазоне `[0, dx)`, что эквивалентно решению `p = 2 * rest - dx` из оригинальной формулы Ву, но не даёт отрицательных промежуточных значений. Пиксели смешиваются с уже нарисованными: `c = (c_линии * cover + c_фона * (255 - cover)) / 255`. Концы отрезка закрашиваются полностью, суммарное покрытие равно длине отрезка.
- `Task2.DrawBresenham(image, from, to, color)` и `Task2.DrawLine(image, from, to, color, algorithm)` — запись отрезка в `Bitmap` выбранным способом. Пиксели за пределами холста пропускаются, поэтому отрезок можно задавать точками вне видимой области.

Оба алгоритма приводят отрезок к виду, где шаг идёт по `x`, и только после построения возвращают координаты на место, поэтому крутые, пологие, горизонтальные и вертикальные отрезки обрабатываются одинаково. Цвет выбранного отрезка задаётся той же кнопкой **«Граница»**, что и для контуров, чтобы сравнивать результаты на одном холсте: Брезенхем даёт ступенчатую границу, Ву — плавный градиент по краям.

Проверки в `Checks/Program.cs` покрывают число точек, связность, отклонение от идеальной прямой, независимость от направления, инвариант покрытия Ву, отсутствие записи за пределами холста и в нулевые пиксели.
